# Flask 3 stack. These five move together or not at all: Flask-JWT-Extended
# 4.5.3 and Flask-Limiter 3.5.0 were both pinned against Flask 2.x, so bumping

# Auth + crypto (JWT, bcrypt, x509)
# 2.13.0 clears six advisories, including CVE-2026-32597: PyJWT accepted unknown `crit` header
# extensions, contrary to RFC 7515. This service signs and verifies its own
# HS256 tokens with its own JWT_SECRET (api/core/auth.py), so the practical
# exposure is low — but it is a small, same-major bump, so there is no reason
# to carry the finding.
PyJWT==2.13.0
python-jose==3.4.0
bcrypt==4.0.1
# cryptography 42.0.8 (CVE fixes); pyOpenSSL bumped in lockstep because
# pyOpenSSL 23.2.0 caps cryptography at <42.
cryptography==42.0.8
pyOpenSSL==24.1.0
# authlib removed 2026-08-06. Nothing in this service imported it — one grep hit
# across the whole repository, and that hit was this line — and `pip show` in a
# fully installed environment reported no reverse dependencies. It appears to
# have come along when CE was split out of the full platform.
#
# It was not free to keep: authlib 1.3.2 carries CVE-2026-27962, an
# authentication bypass via JWK header, which Trivy reports as CRITICAL. A
# vulnerability in code nothing calls cannot be exploited, but it still fails
# the scan, and every reader has to re-derive that reasoning. Deleting it closes
# the finding outright. JWT handling here is PyJWT (see api/core/auth.py).

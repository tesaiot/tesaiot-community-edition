# Credentials for this example

Everything here is generated by **your own** Community Edition install. There is
no hosted service involved: use the Admin UI of the instance you installed, at
whatever address `install.sh` printed when it finished.

## Files this example reads

The C client opens these by exact name. They are **not** the names inside the
downloaded ZIP, so the bundle cannot simply be extracted here — copy each part
to the name below.

| File | Needed for | Where it comes from |
|---|---|---|
| `ca.pem` | both modes | `config/tls/ca-bundle.pem` of your install |
| `device_id.txt` | both modes | the device id you registered |
| `api_key.txt` | **both modes** | `POST /api/v1/devices/<id>/regenerate-api-key` |
| `mqtt_username.txt` | serverTLS | the device id |
| `mqtt_password.txt` | serverTLS | `POST /api/v1/devices/<id>/reset-mqtt-password` |
| `client_cert.pem` | mTLS | `<device_id>.pem` from the certificate bundle |
| `client_key.pem` | mTLS | `<device_id>.key` from the certificate bundle |

`api_key.txt` is required in mTLS mode too. The client sends the device id as
the MQTT username and the API key as the password, and Community Edition's auth
webhook rejects an empty password before it ever looks at the client
certificate — the broker answers `bad_username_or_password` and the TLS
handshake having succeeded tells you nothing.

## Security

Never commit certificates or private keys. This directory is already in
`.gitignore`.
